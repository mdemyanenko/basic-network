# 7. Краткие заметки для защиты

## Что сделано

В проекте построена сеть предприятия с центральным офисом, филиалом и условной сетью интернет. `Router2` имитирует провайдера. Центральный офис выходит в интернет через NAT на `Router0` и `Router1`. Между центральным офисом и филиалом построены GRE-туннели, которые защищены IPsec.

На multilayer-коммутаторах центрального офиса настроен HSRP через команду `standby`. Поэтому ПК используют виртуальный gateway `.1`, а при отказе активного multilayer-коммутатора роль шлюза может перейти на второй multilayer-коммутатор.

## Логика маршрутизации

Между маршрутизаторами используется BGP:

- BGP до провайдера нужен только для underlay-связности;
- корпоративные маршруты между офисом и филиалом передаются OSPF через GRE-туннели;
- приватные LAN-маршруты не передаются провайдеру напрямую.

Внутри центрального офиса используется OSPF между edge-роутерами и multilayer-коммутаторами.

## Что показать преподавателю

1. `show ip bgp summary` на `Router0`, `Router1`, `Router2`, `Router3`.
2. `show ip ospf neighbor` на `Router0`, `Router1`, `MultilayerSwitch0`, `MultilayerSwitch1`.
3. `show standby brief` на `MultilayerSwitch0` и `MultilayerSwitch1`.
4. `show interface tunnel10` и `show interface tunnel20`.
5. `show crypto isakmp sa` и `show crypto ipsec sa`.
6. `show ip nat translations` после ping `8.8.8.8` из центрального офиса.
7. Ping из центрального офиса в филиал.
8. Проверку, что гостевой `PC2` не ходит в корпоративные подсети.

## Короткий вывод

Проект показывает сеть с разделением ролей: OSPF внутри офиса и поверх GRE-туннелей, простой BGP между физическими роутерами, NAT для выхода в интернет и защищенный GRE over IPsec между центральным офисом и филиалом.
